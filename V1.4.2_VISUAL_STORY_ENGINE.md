# V1.4.2 — Action-Based Visual Story Engine

## Goal

Upgrade visual planning from keyword/object matching to **historical story-unit matching**.

The system should answer:

> What historical action or relationship must the viewer see?

rather than:

> Which noun from the narration can be illustrated?

## Visual Story Unit

Each scene now plans:

- `visual_fact` — concrete historical fact represented by the frame.
- `visual_action` — visible action/relationship; never just an isolated object.
- `primary_subject` — main visible subject.
- `visual_entities` — specific people, institutions, or objects when useful.
- `scene_context` — historical place, period, and environment.
- `shot_type` — framing strategy such as wide, medium action, close-up, detail.
- `composition` — spatial relationship between subject, action, supporting elements, and environment.
- `must_show` / `avoid` — concrete visual constraints.
- `search_queries` — historical queries built around the visual fact and action.

## Source ranking

Real-source candidates are ranked using:

1. Visual intent match
2. Event specificity
3. Information density
4. Base query relevance

Intent matching considers subject, action, must-show elements, entities, context, and composition.

An isolated object should not satisfy an action scene merely because the object appears in the narration.

## AI fallback

AI reconstruction receives the full visual story unit and is instructed to depict:

**who/what + does what + with which supporting element + where/when**

rather than generating a keyword collage.

## Storyboard QA

Before visual resolution, the pipeline checks that:

- every scene has a concrete visual action;
- visual planning is not dominated by one visual type;
- the same primary subject is not repeatedly used across the storyboard.

The system remains content-agnostic: no event-specific visual rules are introduced.
